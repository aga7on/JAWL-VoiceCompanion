## Matching method and coverage

The ledger frame IDs are `01_ru_trailer@00` … `@09`; the replay uses unrelated `qwen-frame-N` / `scene-N` identifiers. There is no explicit submitted-frame filename ↔ Qwen frame ID mapping, and Qwen scene IDs are not the hand-labeled scene IDs. The fixture's `TimedFixtureCapture` selects `frames[int(elapsed / interval_s)]`, so we associate the six distinct saved captions **approximately** with `floor(observed_at - started_at)` for its 1-second cadence. This identifies the frame slot implied by the harness, but remains an approximate join because the artifact does not store the source filename on each submission and its wall-clock start is not the capture adapter's monotonic start. The replay saves 3 current-delivery records and 4 recent-event records, with frame 8 duplicated across those collections. It does not save all seven raw inference responses; frame 3 text is truncated in its event-history rendering. Thus a complete per-request accuracy denominator and a quantitative score are impossible from these artifacts. The following is a qualitative claim audit of the six distinct recoverable captions only.

## Separate text score

The ledger records visible trailer overlays but does not independently transcribe them, because exact lettering is not reliably readable in the 1-fps contact sheet. Qwen frame 7 returned corrupted text; this is a clear unusable-text result, while exact word-level correctness/CER remains unscorable. Other captions either omit the overlay or say only “text in Russian”; that establishes possible text presence, not recognition. Use a human-verified higher-resolution transcription or OCR reference before scoring exact title/date accuracy.

## Interpretation

On recoverable content, the replay often identifies the broad visible setting and people, but it makes one clear actor/action-direction error in the outdoor carry sequence, adds emotional/action interpretation that the stills do not establish, and produces corrupted Russian text. Claims about cigarette use and some fine scene details remain ambiguous rather than proven hallucinations. The final `composed_now` field is sampled after the drain, when the current caption has expired; it contains only recent history. It must not be treated as the actual brain input during the delivery callbacks. `brain_result` is null, so this artifact cannot score Hikari uptake or current-vs-history answer behavior.

The strongest next discriminator is to preserve a per-request mapping from `frame_id` to the exact source frame filename / clip-local timestamp, plus every raw caption and the atomic brain-bound snapshot. Then repeat the same ten-frame trailer with the existing hand labels, scoring entity support, actor-role correctness, text separately, abstention, and current/history answer selection. Extend to other clips only after the mapping and reference annotations exist. Do not report aggregate accuracy from this partial event summary.

## Exact-trace replay with managed CPU launch arguments

A follow-up replay used the current managed launch flags from `scripts/run_integrated_profile.ps1` (`--mmproj`, CPU-only devices, `--jinja`, `--reasoning off`, four threads, prompt caches disabled) and the same ten sampled trailer frames. The harness now records each accepted submission's source JPEG, clip-local sample time, frame/scene IDs, and image SHA-256, and records every transport attempt including fallback budget and raw caption. Artifact: `runtime/instances/goal-trailer-visual-replay-20261024/provenance-rerun4-20261024.json`; the temporary CPU server was stopped after the run.

The replay submitted 8 frames, made 7 successful completions from 7 unique sampled frames, replaced 1 pending frame, and delivered 3 observations. Four completed prior-scene results were rejected from the current channel. There were zero stale drops, inference errors, or capture errors. Delivery age was p50 3.19 s / p95 3.81 s. The last current caption was 8.5 s old by the final post-drain snapshot and had correctly expired from `now`.

The exact trace confirms the scene-3 actor-role error: at `trailer-03.jpg` (local 2 s), the ledger says the man supports the woman across his shoulder/back, while Qwen says the woman carries the man. At `trailer-07.jpg` (6 s), Qwen emits corrupted Russian text; the ledger marks the overlay unreadable at contact-sheet resolution, so text CER remains unavailable. At `trailer-09.jpg` (8 s), Qwen says the man is smoking, while the sampled-frame ledger supports only a small bright point near his face; that claim remains unresolved, not a confirmed hallucination. Broad people/outdoor and profile descriptions are generally supported. One frame was coalesced before inference, so the test also shows the queue can miss a rapid-cut sample even when inference and freshness gates behave correctly.

Two diagnostic launches before this managed-argument run were invalid: one omitted the projector and returned HTTP 500; another used default reasoning parsing, where the model placed its output in `reasoning_content` and the caption transport saw empty content. These runs are retained only as launcher diagnostics and are excluded from quality scoring. The managed launch resolved that issue. This is still a ten-second fixture replay, not physical capture, audio-video alignment, brain uptake, or 24/7 acceptance.
