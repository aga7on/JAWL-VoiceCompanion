## 3. Подтверждённые факты репозитория и открытые гипотезы

### 3.1 Подтверждённые факты (Verified Code / System Evidence)
1. **Очередь и финализация голосового цикла (`app-voice-lifecycle`)**:
   - В отчёте от 2026-10-29 зафиксирован результат Node gate: 124 теста, 118 прошли, 6 упали в сценариях `flush`, `finalization`, `overlap` и HTTP 409 conflict ([react-perception-audit](react-perception-audit-20261029.md)). Это исторический результат; в этом аудите Node gate повторно не запускался.
   - Уточнение по уже сохранённым артефактам той же проверки: после исправлений `node-gate-after-mic-buffer.log` показывает 124/124, а финальный `node-gate-final.log` — 125/125, 0 failures. Значит, шесть отказов были устранены до этого отчёта; пункт «повторить Node gate» больше не является открытой P0-ошибкой. Код сейчас не менялся.
   - Буферизация микрофона расширена до 60 с, но логика разрешения конфликтов состояний оставалась открытой на момент [mic-backpressure-audit](mic-backpressure-audit-20261029.md).
2. **Отсутствие кэширования префикса в Gemini Loopback Relay**:
   - В live-аудите 2026-10-29 зафиксирован `prompt_reuse = 0` ([react-perception-audit](react-perception-audit-20261029.md)). Следствие для TTFT и стоимости контекста — ожидаемый риск, но отдельное сравнение задержки с кэшем и без него здесь не проводилось.
3. **Вычислительная нагрузка аудиоанализа на CPU**:
   - Для `EmbeddingGemma 2` измерено около 1.14 с на 10-секундный аудиоклип при одном потоке ([STATE](../STATE.md), [realclip-audio-describer](realclip-audio-describer-20261029.md)). Это измеренная стоимость вызова; связь фоновых запусков на шуме с пиками задержек ReAct этим измерением не подтверждается. Нужен отдельный shared-load тест.
4. **Дрейф ядра (Kernel Upstream Drift)**:
   - Зафиксирован файл изменений `patches/kernel/owned-deviations.patch` (>45 000 строк: 92 добавленных, 89 изменённых файлов относительно снапшота `jawl-20260906-daily-v2`). Требуется строгая изоляция расширений Companion на внешней границе.

## 4. Обзор arXiv:2608.05703 и проект локального эксперимента

### 4.1 Анализ публикации
- **Статья**: [arXiv:2608.05703](https://arxiv.org/abs/2608.05703) — *StreamArena / StreamMind (2026)*.
- **Ключевая идея**: двухуровневая потоковая архитектура (Two-Tier Streaming Architecture). Первый уровень — ультра-низколатентный интерактивный контур мониторинга и реакций; второй уровень — асинхронная персистентная память, агрегация контекста и извлечение знаний.
- **Статус верификации**: результаты статьи являются исключительно **заявлениями авторов (Author Claims)**. В локальной среде JAWL-VoiceCompanion код и бенчмарки статьи **НЕ запускались (Not run locally)**.

### 4.2 Дизайн фальсифицируемого эксперимента в JAWL
- **Цель**: проверить, снижает ли разделение сенсорного потока JAWL на быстрый реактивный срез и асинхронный фоновый индекс нагрузку на планировщик без потери релевантности памяти.
- **Метрики измерения**:
  1. *Live Event Detection Latency*: время обнаружения событий интерфейса и речи (целевой порог <250 мс).
  2. *Memory Recall*: точность извлечения контекста на горизонтах t - 2 мин и t - 15 мин (Recall@K).
  3. *Ресурсы*: CPU usage (%), RSS memory (MB) основного процесса.
  4. *Качество потока*: доля отброшенных устаревших пакетов (`stale drops`, %), частота ложных срабатываний (`false positives`, %).

## 5. Приоритетные направления работ
- **P0 (актуальное состояние)**: голосовой lifecycle имеет сохранённый успешный финальный gate 125/125 (`runtime/continuity-audit-20261029/node-gate-final.log`); повторное исправление не требуется. В текущем живом health-check Companion остаётся `degraded` только из-за `ambient_audio=waiting_for_samples`: loopback открыт, но свежие PCM-сэмплы не поступают. В `config/runtime.manifest.json` устройство было пустым вопреки runbook и ранее указанному владельцем выходу; теперь закреплено `DigitalOutput (NVIDIA High Definition Audio)`. Уже работающий процесс эту настройку не перечитает, поэтому результат будет проверяем после следующего штатного запуска с воспроизводимым звуком на этом выходе. Причину нулевых сэмплов до такого прогона нельзя считать окончательно доказанной.
- **Открытая проверка, не дефект кода**: измерить влияние prefix cache на Gemini Relay контролируемым сравнением. `prompt_reuse=0` само по себе не доказывает регрессию задержки.
- **P1 (Производительность)**: энергетический гейтинг EmbeddingGemma 2 через лёгкий YAMNet (прогон только при RMS > порога и флаге речи/музыки); вынос сенсоров восприятия в изолированный воркер с жёстким квантом времени.
- **P2 (Исследования)**: подготовка тестового стенда для потокового ASR и валидация схемы StreamArena на синтетическом датасете сессий.
