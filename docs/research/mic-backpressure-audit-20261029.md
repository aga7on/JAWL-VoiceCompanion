# Микрофонная очередь распознавания — 29 октября 2026

## Дефект

Desktop пакетировал PCM примерно по 250 мс, но очередь `/api/voice/audio`
принимала максимум шесть запросов. Следующая пачка считалась фатальной
backpressure-ошибкой и останавливала микрофон. Скорость сети временно выключала
сам источник, хотя уже захваченный звук ещё можно было сохранить.

## Исправление

- При заполненной очереди новые PCM-фреймы остаются в bounded memory buffer;
  захват микрофона продолжает работать. При освобождении очереди буфер уходит
  пачками до двух секунд.
- UI сообщает, что ASR отстаёт и звук временно буферизуется; когда очередь
  уменьшается, возвращает обычный статус прослушивания.
- Финализация ждёт AudioWorklet boundary и полного drain аудио. `session_id` и
  `correlation_id` не меняются, пока последняя буферизованная пачка не принята;
  только потом отправляется `/api/voice/end`.
- Верхняя граница временного PCM-буфера — 60 секунд. Если backend не восстановил
  скорость за это время, захват останавливается с отдельным объяснением, чтобы
  не переполнить память и не представить неполную реплику как полную.

## Проверка

- Regression: шесть занятых слотов плюс следующая PCM-пачка → микрофон остаётся
  активным; после завершения запроса пачки догоняют очередь.
- Regression финализации при backpressure: все семь audio requests завершены с
  теми же идентификаторами реплики, затем только один `/api/voice/end`.
- Голосовой lifecycle suite: 28/28 PASS. Весь затронутый Node gate: 125/125 PASS.
  `node --check desktop/app.js` и scoped `git diff --check` прошли.

Проверка — контролируемый browser harness, не физический microphone и не live
ASR. На момент закрытия live profile и endpoint `8045` завершились вместе с
управляющим процессом; поэтому изменение пока не проверено на текущем сервисе.
