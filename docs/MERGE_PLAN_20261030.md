# MERGE-PLAN 2026-10-30 — безопасное поглощение внешних идей

> Мандат: «составь merge-план безопасный, который нашу философию не ломает, и
> смерджи автономно, но ТОЛЬКО если у аналогов лучше, чем у нас».
> Философия-инварианты (нерушимы): capability в ядро / GPU и presentation
> наружу; owned kernel (ADR-049); admission/receipt/delivery гарантии;
> speech-first; канон моделей (ADR-048); ограниченность (boundedness) всех
> буферов и очередей; локальная работа без облаков как обязательства.

  Потерь нет.

## 1. Скользящее окно сенсорики — ЕСТЬ (сверка с SHSD)

| Механизм | SHSD (aga7on/SHSD) | У нас | Вердикт |
|---|---|---|---|

| Очереди L1/L2/L3 | 3 async job queues | 2 worker-потока (processing/description/soundscape) + background-очереди памяти | достаточно; 3-уровневая декомпозиция — backlog, не сейчас |

## 2. TTS / DuplexCascade — механизмы ЕСТЬ, «оформлено» в SPEECH_FIRST_MECHANISM.md

- Уже реализовано (и теперь формально описано в
  [SPEECH_FIRST_MECHANISM.md](SPEECH_FIRST_MECHANISM.md)): speech-first gate
  (ядро), инкрементальный TTS на подходе генерации (`live_speech`), провизорная
  речь без LLM (`voice_preface`), микро-туры с 6 control-токенами
  (`duplex_cascade`), семантический конец хода (`turn_policy`).
- DuplexCascade (sbintuitions) лучше нас в одном: control-токены генерирует
  **сам обученный LLM** (full-duplex fine-tune). Мы это НЕ мержим: требует
  новой обученной модели (нарушение ADR-048) и ломает «мозг = единственный
  когнитивный рантайм». Слот под замену зарезервирован (`MicroTurnDecision`
  interface) — вернёмся при смене канона моделей.

## 3. Project-N-E-K-O (N.E.K.O) + два аналога — что почерпнуть

**N.E.K.O** (3.1k ⭐, Python): сильная продуктовая широта — проактивные
инициативы (`proactive_chat`, `proactive_delivery`), 5-уровневая память
(рабочая/近期/факты/рефлексия/личность), event bus (`agent_event_bus`,
`lifecycle_bus`), мульти-avatar, плагины, 14+ облачных провайдеров.
Слабость: облачная мульти-провайдерность противоречит нашей local-first
гибридной философии; когнитивное ядро слабее наших admission/receipt/delivery
гарантий. **Черпаем только идеи оформления (backlog):** схема событий
проактивной доставки; у нас проактивный контур (daily/scheduled loops) уже
есть, его события можно полировать по образцу. В ядро — ничего.

**pipecat** (voice-pipeline framework): SmartTurn — обученный ONNX-классификатор
конца хода по аудио (точнее наших текстовых эвристик) + sentence aggregator.
Агрегатор предложений у нас уже есть (`live_speech`). SmartTurn требует новую
модель → ADR-048 запрещает; интерфейс замены готов (см. §2). **НЕ мержим.**

**Open-LLM-VTuber**: Silero-VAD + классический каскад с прерываниями. Наш
VAD-free подход (control-токены + duck→stop) строго богаче. **НЕ мержим.**

## 5. Правила безопасности при мерже (соблюдены)

1. Никаких изменений в owned kernel снапшоте (digest 07614177 не тронут).
2. Никаких новых моделей/весов/артефактов (канон ADR-048).
3. Все буферы ограничены (bounded cache 32/120 с, как и весь код продукта).
4. Точечные правки продукта `src/jawl_voicecompanion/`, без big-bang.
5. Каждое изменение покрыто тестами и запушено отдельным коммитом.
6. Env-базовая линия падений не выросла (diff FAILED-списков до/после = пуст).

## 6. Backlog (осознанно отложено)

- Замена текстовых эвристик конца хода на обученный классификатор за
  `MicroTurnDecision` интерфейсом (нужен новый канон моделей → ADR).
- 3-уровневая декомпозиция сенсорных задач (L1/L2/L3 по образцу SHSD) —
  при росте нагрузки на CPU.
- Схема событий проактивной доставки по образцу N.E.K.O (product-side).
- Interval watermark'ы для возобновляемого анализа — когда появится
  потребитель (пока live-поток не возобновляемый).
