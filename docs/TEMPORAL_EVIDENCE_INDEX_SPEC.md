## 1. Назначение и архитектурные инварианты

`JAWL Temporal Evidence Index v1` (`JTE1`) — бинарный потоковый sidecar-индекс, сопровождающий непрерывную циклическую A/V-запись рабочего стола/игры. Он решает задачу **мгновенного ретроспективного поиска ключевых кадров и областей интереса (ROI)** по запросам вида «Что там только что выпало?», «Какой код был на двери?», без необходимости повторного дорогостоящего декодирования всего видеопотока и прогона тяжелых нейросетей по каждому кадру.

### Архитектурные инварианты:

1. **Non-blocking & Zero Ingestion Penalty (Защита первоисточника)**:
   - Индексирование никогда не блокирует контур видеозахвата.
   - Если очередь вычисления признаков переполняется (нагрузка на CPU), запись видео продолжается бесперебойно, а в индексе выставляется флаг `FLAG_METADATA_DROPPED (0x0001)`.
   - Первоисточник (A/V-поток) имеет абсолютный приоритет над метаданными.

2. **Unified Microsecond Monotonic Timeline (`pts_us`)**:
   - Временная метка `pts_us` (uint64) является единой и монотонной для:
     - Видеокадров захвата (DXGI / ScreenCaptureAdapter);
     - Аудиопакетов микрофона и системного звука (WASAPI);
     - Смены визуальных сцен (`SceneState.version`);
     - Реплик диалога (`ConversationHistory`, `TurnArbiter`).
   - Исключается привязка к теоретической частоте кадров (60 FPS); дропы кадров и пропуски рендеринга точно отражаются в реальной дельте `pts_us`.

3. **Crash Recovery & Segmentation (Отказоустойчивость)**:
   - Индекс разбивается на короткие автономные сегменты (по умолчанию 5–10 секунд), совпадающие по границам с ключевыми кадрами (GOP) видеоархива.
   - Каждый кадр защищён индивидуальной контрольной суммой `CRC32`.
   - При внезапном сбое процесса (краш, отключение питания) усечённый последний кадр отбрасывается, а все предшествующие кадры сегмента восстанавливаются без повреждения данных.

4. **Strict Memory & Disk Budget**:
   - Размер записи кадра фиксирован: **точно 256 байт** (выравнивание по границам степеней двойки, кэш-линий и секторов диска).
   - При 60 FPS: $60 \times 256\text{ байт} = 15.36\text{ КБ/с} \approx \mathbf{55.296\text{ МБ/час}}$.
   - Нулевой расход VRAM (вычисления на CPU / SIMD / целочисленной арифметике).

## 2. Бинарная раскладка формата (Wire Format)

### 2.1. Заголовок сегмента (`Segment Header`, 32 байта)

| Смещение | Тип | Имя поля | Описание |
|---|---|---|---|
| `0x00..0x03` | `char[4]` | `magic` | Сигнатура файла: `b"JTE1"` |
| `0x04..0x05` | `uint16` | `version` | Версия схемы: `1` |
| `0x06` | `uint8` | `grid_h` | Высота пространственной матрицы: `21` |
| `0x07` | `uint8` | `grid_w` | Ширина пространственной матрицы: `30` |
| `0x08..0x0B` | `uint32` | `segment_id` | Идентификатор сегмента (монотонный счётчик) |
| `0x0C..0x13` | `uint64` | `start_pts_us` | Монотонное время первого кадра сегмента (мкс) |
| `0x14..0x17` | `float32` | `fps_hint` | Номинальный FPS видеопотока (например, `60.0`) |
| `0x18..0x1F` | `uint64` | `reserved` | Зарезервировано под выравнивание (0x00) |

---

### 2.2. Запись кадра (`IndexFrameRecord`, фиксированные 256 байт)

Запись разделена на 4 функциональные секции:

```
+-------------------------------------------------------------------------+
| Section 1: Perceptual Header (32 bytes)                                 |
| frame_id(4) | segment_id(4) | pts_us(8) | scene_ver(2) | flags(2)       |
| global_motion(4) | sharpness(4) | edge_text(4)                          |
+-------------------------------------------------------------------------+
| Section 2: Spatial Bitmasks (160 bytes)                                 |
| local_change_mask (79B bitmask + 1B pad = 80B)                          |
| ui_likelihood_mask (79B bitmask + 1B pad = 80B)                         |
+-------------------------------------------------------------------------+
| Section 3: High-Priority Candidate ROIs (48 bytes)                      |
| roi_count(4)                                                            |
| roi_0: [x(4), y(4), w(4), h(4), conf(4)] (20B)                          |
| roi_1: [x(4), y(4), w(4), h(4), conf(4)] (20B)                          |
| roi_pad(4)                                                              |
+-------------------------------------------------------------------------+
| Section 4: Tail & Integrity (16 bytes)                                  |
| reserved (12B)                                                          |
| crc32 (4B, over payload bytes 0x00..0xFB)                               |
+-------------------------------------------------------------------------+
Total: exactly 256 bytes
```

#### Детальная спецификация полей записи:

| Смещение | Длина | Тип | Поле | Описание |
|---|---|---|---|---|
| `0x00..0x03` | 4B | `uint32` | `frame_id` | Глобальный порядковый номер кадра |
| `0x04..0x07` | 4B | `uint32` | `segment_id` | Привязка к A/V-сегменту хранилища |
| `0x08..0x0F` | 8B | `uint64` | `pts_us` | Метка времени на общей монотонной шкале |
| `0x10..0x11` | 2B | `uint16` | `scene_version` | Версия сцены (`SceneState.version`) |
| `0x12..0x13` | 2B | `uint16` | `quality_flags` | Битовая маска флагов качества (см. разд. 2.3) |
| `0x14..0x17` | 4B | `float32` | `global_motion_score` | Нормированная дельта движения сцены [0.0..1.0] |
| `0x18..0x1B` | 4B | `float32` | `sharpness_score` | Дисперсия лапласиана / градиента вне HUD |
| `0x1C..0x1F` | 4B | `float32` | `edge_text_score` | Плотность высокочастотных текстовых переходов |
| `0x20..0x6F` | 80B | `uint8[80]` | `local_change_mask` | Битовая маска изменений 21×30 тайлов (630 бит + 10 бит паддинг) |
| `0x70..0xBF` | 80B | `uint8[80]` | `ui_likelihood_mask`| Битовая маска статического интерфейса/HUD (630 бит + 10 бит паддинг) |
| `0xC0..0xC3` | 4B | `uint32` | `roi_count` | Число кандидатов ROI (0..2) |
| `0xC4..0xD7` | 20B | `uint32[4]+f32` | `roi_0` | Первый кандидат `[x, y, w, h]` в пикселях + `conf` |
| `0xD8..0xEB` | 20B | `uint32[4]+f32` | `roi_1` | Второй кандидат `[x, y, w, h]` в пикселях + `conf` |
| `0xEC..0xEF` | 4B | `uint32` | `roi_pad` | Паддинг секции ROI до 48 байт (0x00) |
| `0xF0..0xFB` | 12B | `uint8[12]` | `reserved` | Зарезервировано под расширения протокола v1.1 |
| `0xFC..0xFF` | 4B | `uint32` | `crc32` | Контрольная сумма CRC32 первых 252 байт записи |

---

### 2.3. Флаги качества (`quality_flags`)

| Бит | Название константы | Значение | Назначение |
|---|---|---|---|
| `0x0001` | `FLAG_METADATA_DROPPED` | 1 | Очередь индексатора была перегружена; метаданные неполные, но видеокадр сохранён |
| `0x0002` | `FLAG_OVEREXPOSED` | 2 | Пересвет / белая вспышка (взрыв, строб) |
| `0x0004` | `FLAG_UNDEREXPOSED` | 4 | Слишком тёмная сцена (чёрный экран, затемнение) |
| `0x0008` | `FLAG_HIGH_MOTION_BLUR` | 8 | Сильный смаз движения (текст заведомо не читаем) |
| `0x0010` | `FLAG_OCR_CANDIDATE` | 16 | Кадр содержит плотный высококонтрастный текстовый кластер |
| `0x0020` | `FLAG_UI_TARGET` | 32 | Событие локализовано внутри зон HUD/интерфейса |
| `0x0040` | `FLAG_CORRUPTED_FRAME` | 64 | Дефект видеозахвата (битый буфер DXGI) |

## 3. Вычисление признаков «на лету» (Live Ingestion)

Чтобы индексация укладывалась в **< 0.5 мс на кадр на CPU**, используются легковесные алгоритмы:
1. **Downsampled Luma (Целочисленное преобразование)**:
   - $\text{Luma} = (R + 2G + B) \gg 2$ на уменьшенном разрешении ($320 \times 180$).
2. **Local Change Mask (21×30 тайлов)**:
   - Инкрементальная пространственная матрица вычисляет блочные средние и дисперсии яркости: $630$ тайлов.
   - Тайлы с дельтой выше порога шума формируют 79-байтовую битовую маску (`packbits`).
3. **Soft HUD Mask (`ui_likelihood_mask`)**:
   - Оценивается по экспоненциально взвешенной истории локальной дисперсии: тайлы с околонулевой дисперсией на фоне движущегося окружения маркируются как HUD (HP-бар, счетчик патронов, миникарта).
4. **World Sharpness**:
   - Быстрый дискретный градиент вне HUD:
     $S_{\text{world}} = \text{Var}\left(\nabla \text{Luma} \odot (1 - \text{UI\_Mask})\right)$.

## 4. План фазонезависимого тестирования (Round 11 Verification)

Для устранения фазового артефакта, обнаруженного в предварительном прогоне (где Uniform K=12 случайно совпал по фазе с центрами событий), утверждается методика фазонезависимого бенчмарка:

1. **Randomized Temporal Phase Jitter**:
   - Начало поискового 10-секундного окна смещается случайным псевдослучайным сдвигом $\Delta t \in [-3.0\text{с}, +3.0\text{с}]$ относительно центра события.
2. **Multi-Seed Evaluation (5 сессий, 100 прогонов)**:
   - Генерация 5 независимых сидов для процедурного полигона стимулов.
3. **Тестируемые селекторы**:
   - `Uniform` ($K=8, 12$);
   - `Spatial-Only` ($K=8, 12$);
   - `Hybrid One-Pass` ($K=8, 12$);
   - `Hybrid Adaptive` ($K=8, 12$);
   - `Oracle Upper Bound` ($K=1, 12$).
4. **Критерий превосходства**:
   - Гибридный селектор признаётся победителем, если его средний Hit Rate по $N=100$ испытаниям превосходит Uniform с доверительным интервалом $p < 0.01$, а Hit Rate на `T-Motion` превосходит Spatial-Only минимум в 3 раза.
