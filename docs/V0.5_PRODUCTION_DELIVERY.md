## 1. Ценностный сценарий и онбординг (Value Proposition & Day 1 Scenario)

### 1.1. Ценностное предложение для владельца
`JAWL-VoiceCompanion-V0.5` — это персональный голосовой AI-компаньон для постоянного присутствия на рабочем столе Windows 11. В отличие от браузерных чат-ботов, компаньон:
1. **Постоянно виден на экране:** Компактный 3D-аватар (VRM) в режиме хамелеона (HUD Always-on-Top `360x540`) располагается поверх рабочих окон, не перегружая рабочий стол.
2. **Обладает общим сенсорным контекстом с владельцем:** Компаньон видит экран (OCR и VLM-дескриптор) и слышит разрешённый системный звук приложений (YouTube, Discord, плееры через WASAPI loopback) с автоматическим подавлением собственной речи и эхо-петель.
3. **Разговаривает со скоростью естественной беседы:** Задержка от конца фразы до первого слышимого звука составляет **~1.8–2.2 секунды** благодаря параллельному механизму `Stream-Before-Close` и квантованному движку OmniVoice TTS.
4. **Уважает суверенитет и безопасность:** Единое каноническое ядро JAWL владеет памятью, целями и политиками безопасности. Никакой сторонний скрипт не пишет в память без решения ядра.
5. **Энергоэффективен:** В моменты неактивности или скрытия окна рендерер Three.js автоматически ставится на паузу, снижая потребление GPU до **0%**.

### 1.2. Сценарий Day 1: От чистого запуска до живого диалога
1. **Запуск одной командой:**
   ```powershell
   pwsh -ExecutionPolicy Bypass -File scripts\run_integrated_profile.ps1 -StartDesktopShell
   ```
2. **Preflight & Автономная оркестровка:**
   - Читается канонический манифест `config/runtime.manifest.json`.
   - Проверяется доступность портов (`Control: 2367`, `JAWL: 8770`, `OmniVoice: 9890`, `Brain: 8990`).
   - Поднимаются локальные воркеры: `SenseNova Loop 9B` на GPU 1 (RTX 5080) и `OmniVoice 0.6B` на GPU 1.
   - Инициализируется Electron-оболочка `desktop/main.js` и открывается шлюз `http://127.0.0.1:2367/app`.
3. **Первое пробуждение аватара:**
   - 3D-модель Луны загружается в Three.js с плавным блендингом освещения MToon.
   - Камера автоматически выбирает поясной портрет (**Bust Shot**), фокусируясь на лице и торсе.
   - Персонаж выполняет приветственный взмах рукой (`motion: wave`) и произносит голосовое приветствие.
4. **Ежедневный рабочий цикл:**
   - Владелец работает за ПК: компаньон находится в правом нижнем углу в режиме Always-on-Top.
   - При необходимости кликнуть сквозь модель нажимается хоткей `Ctrl+Shift+G` (Chameleon Click-Through).
   - Владелец задаёт вопрос голосом в микрофон или вводит короткую реплику в `#hud-quick-bar` — компаньон мгновенно отвечает голосом, а текст появляется в парящем баббле над головой.
   - При необходимости детальной работы (просмотр памяти, переключение моделей, просмотр логов) клик по шестерёнке плавно разворачивает окно в студию `1060x720`.

### 2.1. Аппаратный бюджет и распределение ресурсов (Целевая машина)
- **GPU 0 (NVIDIA RTX 4070 Ti, 12 GB VRAM):** Оставлена свободной для дисплея, рабочих приложений и игр пользователя.
- **GPU 1 (NVIDIA RTX 5080, 16 GB VRAM):** Выделена под инференс компаньона:
  * **Brain (SenseNova Loop 9B Preview, Q4_K_M):** 10 993 МиБ VRAM (полный контекст 256K токенов с квантованием KV-кэша `q4_0`, CUDA 13.3, `llama-server.exe`).
  * **TTS (OmniVoice 0.6B):** ~2 500 МиБ VRAM (порт 9890, RTF ~0.2).
  * **Запас VRAM:** ~2.5 ГБ свободного буфера на случай пиковых нагрузок.
- **CPU (24 ядра) & RAM (64 GB):**
  * **ASR (CrispASR + GigaAM v3 Q8_0):** CPU-инференс, скорость 15.9x realtime, потребление RAM ~1.2 ГБ.
  * **Sensory Embedder (EmbeddingGemma 2 ONNX, 768d):** CPU-инференс, время эмбеддинга <25мс.
  * **Screen Describer (Qwen 3.5 0.8B Q4_K_M):** CPU-инференс, 4 потока.

## 3. Системное поведение и синхронизация состояний (State Sync)

### 3.1. Конечный автомат состояний (FSM)
Компаньон функционирует как реактивно-проактивный автомат со следующими состояниями:

```text
       ┌───────────┐      Пользователь заговорил (VAD)       ┌──────────────┐
       │           │ ──────────────────────────────────────▶ │              │
       │   IDLE    │                                         │  LISTENING   │
       │           │ ◀────────────────────────────────────── │              │
       └───────────┘        Тишина > 450мс / Отмена          └──────────────┘
         │       ▲                                                   │
         │       │                                                   │ Завершение реплики
         │       │ Ответ завершён                                    ▼
         │  ┌──────────────┐         Стриминг первого чанка   ┌──────────────┐
         │  │              │ ◀────────────────────────────── │              │
         │  │   SPEAKING   │                                 │   THINKING   │
         │  │              │ ──┐                             │              │
         │  └──────────────┘   │ Barge-in (перебивание)      └──────────────┘
         │                     │ (<50мс немедленный Stop)           │
         │                     ▼                                    │ Ошибка провайдера
         │               ┌───────────┐                              ▼
         └─────────────▶ │   ERROR   │ ◀────────────────────────────┘
            Сбой связи   └───────────┘
```

### 3.2. Синхронизация между слоями системы
1. **AudioWorklet -> ASR Bridge:**
   - Микрофон захватывается на частоте 16 кГц в `AudioWorkletNode` блоками по 2048 сэмплов (~128мс).
   - VAD вычисляет энергию фрейма; при превышении порога активируется флаг `listening` в UI.
2. **SpeechFirstGate -> LiveSpeechSession:**
   - Потоковые токены из `llama-server.exe` или JAWL-шлюза проходят через `SpeechFirstGate`.
   - Как только накоплена первая законченная грамматическая фраза (точка, вопросительный/восклицательный знак или перенос строки), она отправляется в OmniVoice HTTP endpoint до завершения всей генерации.
3. **WebAudio -> LipSync & Three.js:**
   - Аудиопоток декодируется в WebAudio `AudioContext`.
   - `AnalyserNode` извлекает спектральные полосы частот и нормализованную громкость, преобразуя их в морф-таргеты рта VRM (`aa`, `ih`, `ou`, `ee`, `oh`) с интерполяцией 60 FPS.
4. **Electron IPC Sync:**
   - Хоткей `Ctrl+Shift+G` переключает флаг `ignoreMouseEvents(true, { forward: true })`.
   - Событие `jawl-click-through-changed` передаётся в рендерер через `panel-preload.js`, переключая визуальное состояние кнопки `#btn-clickthrough`.

## 4. Границы действий и управление данными (Data Governance)

### 4.1. Политика доступа к операционной системе (HostOS Levels)
Контроль действий на хосте регламентирован контрактом безопасности:
- **Level 0 (Read-Only):** Только пассивный сбор телеметрии (загрузка CPU/RAM, активное окно, статус процессов).
- **Level 1 (User Approval):** Любые операции записи файлов, кликов мыши или нажатий клавиш требуют явного подтверждения владельца в UI (`#approval-dialog`).
- **Level 2 (Supervised Autonomous):** Автономное выполнение задач в пределах безопасного рабочего каталога (`session workspace`); деструктивные системные команды требуют подтверждения.
- **Level 3 (Full Unattended):** Полный доступ для длительных автономных фоновых задач JAWL с возможностью аппаратного `Emergency Stop` (мгновенный сброс через красную кнопку в HUD или вызов `/api/hostos/emergency-stop`).

### 4.2. Иерархия памяти и защита от галлюцинаций (ADR-053)
В проекте реализована строгая четырёхуровневая модель памяти:
1. **Tier 0 (RAM Buffer):** Эфемерный кольцевой буфер восприятия (последние 30 секунд аудио/видео). Очищается при перезапуске.
2. **Tier 1 (Sensory History Store):** Структурированный лог событий (1 час подробных наблюдений, 7 дней сжатых дайджестов).
3. **Tier 2 (VoiceMem / LocalSqliteMemory):** Локальная семантическая память на базе `EmbeddingGemmaSensoryCortex` (768d). Выполняет роль генератора гипотез (спекулятивный контекст). **Не имеет права самостоятельной записи в долгосрочную память.** Формирует событие `MEMORY_CANDIDATE`.
4. **Tier 3 (Canonical JAWL Structured Memory):** Единственный канонический источник правды (SSOT). Только ядро JAWL после валидации фактов переносит кандидата в постоянную память.

### 4.3. Акустическая атрибуция и приватность (ADR-054)
- **Исключение компаньона:** `AppAudioRouter` рекурсивно находит дерево PID текущего процесса компаньона и подавляет захват его выходных звуковых узлов в WASAPI loopback.
- **Атрибуция источников:** Каждая фраза, услышанная из системного звука, тегируется метаданными: `source_app`, `app_category`, `app_title`, `app_pid`. Агент точно знает: фраза прозвучала из YouTube в Chrome или от собеседника в Discord.
- **Нулевое сохранение сырого аудио:** Ни микрофонный звук, ни системный лупбэк никогда не сохраняются в виде постоянных WAV/MP3 файлов на диске (Zero Raw Media Retention). В диск попадают только векторизованные текстовые транскрипты.

## 5. Дисциплинированный план реализации (Phased Plan Execution)

Реализация проекта была разделена на 6 взаимосвязанных фаз консолидации и фазу финальной стабилизации:

```text
[Фаза 1: VoiceMem In-Tree] ──▶ [Фаза 2: CrispASR Consolidation] ──▶ [Фаза 3: Llama-Server GPU1]
            │                                                                │
            ▼                                                                ▼
[Фаза 4: OmniVoice TTS]    ──▶ [Фаза 5: Modern UI/HUD Chameleon] ──▶ [Фаза 6: Portability Hub]
                                                                             │
                                                                             ▼
                                                                  [Финальная стабилизация V0.5]
                                                                  - Stream-Before-Close <2.2s
                                                                  - Bust Shot VRM Camera
                                                                  - 0% GPU WebGL Pause
                                                                  - Полный прогон E2E (18/18)
```

1. **Фаза 1 (VoiceMem in-tree, ADR-053):** Перенос кода в `src/voicemem/`, интеграция легковесного `LocalSqliteMemory` с локальным ONNX-эмбеддером, устранение внешних серверов Qdrant/mem0.
2. **Фаза 2 (CrispASR & GigaAM in-tree):** Консолидация бинарника `runtime/bin/crispasr/crispasr.exe` и весов модели GigaAM v3 RNN-T Q8_0 в дереве репозитория.
3. **Фаза 3 (Llama.cpp Backend на GPU 1):** Сборка кастомного `llama-server.exe` (CUDA 13.3) с поддержкой Looped Transformer для SenseNova-Loop 9B с контекстом 256K токенов.
4. **Фаза 4 (OmniVoice TTS in-tree):** Развёртывание OmniVoice 0.6B в изолированном окружении `runtime/omnivoice-venv/` на порту 9890 с каноническим голосовым референсом.
5. **Фаза 5 (UI/UX Chameleon & HUD):** Реализация двухрежимного интерфейса `desktop/app.html`: компактный Always-on-Top HUD (`360x540`) и студия (`1060x720`).
6. **Фаза 6 (Портативность и ликвидация дрейфа):** Полная отвязка путей от `G:\AI\...`, синхронизация `config/runtime.manifest.json` и скрипта запуска `scripts/run_integrated_profile.ps1`.
7. **Финальная стабилизация V0.5:**
   - Устранение хардкода в `config_hub.py`.
   - Внедрение поясного портрета (Bust Shot) камеры Three.js.
   - Остановка цикла WebGL-рендеринга для снижения потребления GPU до 0% в фоне.
   - Замена блокирующего `window.confirm()` в управлении памятью на двухэтапное инлайн-подтверждение.

   - Исправление извлечения сообщений из диалоговой истории в тестах `tests/test_e2e.py`.

### 6.2. Адаптивное кадрирование Three.js VRM Bust Shot (`desktop/app-scene.js`)
Функция динамически находит мировые координаты костей головы и груди и приближает камеру в компактном режиме:
```javascript
export function applyCameraFraming(vrm) {
    if (!vrm || !vrm.humanoid) return;
    const isCompact = document.body.classList.contains('compact-mode');
    const headNode = vrm.humanoid.getNormalizedBoneNode('head');
    const chestNode = vrm.humanoid.getNormalizedBoneNode('upperChest') || vrm.humanoid.getNormalizedBoneNode('chest');
    
    if (isCompact && headNode && chestNode) {
        const headPos = new THREE.Vector3();
        const chestPos = new THREE.Vector3();
        headNode.getWorldPosition(headPos);
        chestNode.getWorldPosition(chestPos);
        const targetY = chestPos.y + (headPos.y - chestPos.y) * 0.55;
        controls.target.set(0, targetY, 0);
        camera.position.set(0, targetY, 1.45); // Фокус на поясном портрете
    } else {
        controls.target.set(0, 1.15, 0);
        camera.position.set(0, 1.25, 3.4);   // Ростовой план для студии
    }
}
```

### 6.3. Пауза рендеринга Three.js для 0% нагрузки на GPU (`desktop/app-scene.js`)

```javascript
export function setRenderPaused(paused) {
    renderPaused = Boolean(paused);
    if (!renderPaused) {
        clock.getDelta(); // Сброс дельты времени для исключения рывка физики пружин
        requestAnimationFrame(tick);
    }
}
document.addEventListener('visibilitychange', () => setRenderPaused(document.hidden));
window.addEventListener('pagehide', () => setRenderPaused(true));
window.addEventListener('pageshow', () => setRenderPaused(false));
```

## 8. Опыт ежедневного компаньона (Daily Companion Experience)

### 8.1. Эргономика и взаимодействие
- **Минималистичный компактный HUD:** Персонаж не загораживает рабочую область. Текстовый баббл аккуратно расположен над головой персонажа и не перекрывает жестикуляцию и торс.
- **Мгновенный ввод (Quick Prompt Bar):** Для отправки короткой текстовой команды не нужно разворачивать громоздкую боковую панель — достаточно кликнуть в нижний бар HUD и нажать `Enter`.
- **Прозрачность для мыши (Ghost / Click-Through):** При нажатии `Ctrl+Shift+G` компаньон становится полностью прозрачным для кликов мыши, позволяя работать с окнами, расположенными прямо под ним. Кнопка в HUD подсвечивает активный статус клик-сквозь.
- **Борьба с ложными срабатываниями (Barge-in):** Если компаньон говорит, а пользователь начинает говорить в микрофон, компаньон прерывает речь менее чем за **50 мс**, мгновенно переходя в состояние внимательного слушания.
