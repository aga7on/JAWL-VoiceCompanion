## 1. Гармонизация UI: Концепция «Окно-Хамелеон» (Project Airi / N.E.K.O. паттерн)

### Проблема разрозненности
Исторически в проекте образовалось 5 пересекающихся UI-поверхностей:
1. Оригинальный веб-интерфейс `JAWL` (отдельный сервер и настройки);
2. Старая веб-панель `frontend/index.html` (`/` на порту `2367`);
3. Новое приложение `desktop/app.html` (`/app` на порту `2367`, ADR-046);
4. Двухоконный `--legacy-shell` (`desktop/avatar.html` + `avatar-scene.js`);
5. Черновой `rust-client/`.

При этом `avatar-scene.js` уже отстал от `app-scene.js` (в нём нет кастомной пружинной физики `avatar-physics.js`, процедурного контроллера `avatar-motion.js`, мягкого трёхточечного света для MToon и полной авто-калибровки поз VRM 0.x/1.0).

### Целевое решение: Единая поверхность `desktop/app.html` с двумя режимами

Вместо поддержки нескольких фронтендов **единственной точкой входа** становится `desktop/app.html` + `desktop/app-scene.js` в Electron, работающее как **«Окно-Хамелеон»**:

```text
┌─────────────────────────────────────┐       ┌─────────────────────────────────────────────────────────────┐
│        COMPACT HUD MODE             │       │                    STUDIO DRAWER MODE                       │
│     (По умолчанию, 360×540)         │       │              (По клику на ⚙️, 1060×720)                     │
│                                     │       │                                                             │
│     ┌─────────────────────────┐     │       │  ┌────┬─────────────────────────┬────────────────────────┐  │
│     │    💬 Баббл ответа      │     │       │  │ 💬 │                         │  Вкладки (Side Panel): │  │
│     └─────────────────────────┘     │       │  │ 🎭 │                         │  - Чат и история       │  │
│                                     │       │  │ 🎙 │      3D VRM Stage       │  - Мозг и Задачи JAWL  │  │
│            [ 3D VRM ]               │  ◀──▶ │  │ 👁 │   (Тот же WebGL-контекст│  - Слух и Голос        │  │
│             Jawlie                  │       │  │ 🧠 │    без перезагрузки!)   │  - Чувства (Экран/Звук)│  │
│          (Прозрачный фон            │       │  │ 🛠 │                         │  - Гардероб и Физика   │  │
│           Always-on-Top)            │       │  │ ⚙  │                         │  - Настройки фреймворка│  │
│                                     │       │  └────┴─────────────────────────┴────────────────────────┘  │
│   ┌─────────────────────────────┐   │       └─────────────────────────────────────────────────────────────┘
│   │ 🎙   ⏹   👁   🔕   📌   ⚙️ │   │
│   └─────────────────────────────┘   │
│     (Всплывающий при наведении HUD) │
└─────────────────────────────────────┘
```

1. **Режим 1: «Компаньон рядом» (`Compact HUD Mode` — 90% времени)**
   - Компактное окно (`360×540`), поверх окон (`Always-on-Top`), прозрачный/стеклянный фон, без лишних рамок.
   - Скрыты `nav.rail`, `header.top` и правая колонка `div.side` (`body.compact-mode`).
   - Видна только 3D-модель Jawlie и живой текстовый баббл (`#avatar-caption`) над/под ней.
   - При наведении мыши снизу плавно всплывает мини-док (HUD):
     - `🎙` — Микрофон / Дуплекс;
     - `⏹` — Быстрый Stop речи (не отменяющий фоновую задачу JAWL);
     - `👁` — Быстрая пауза/включение чувств (захват экрана и системного звука);
     - `🔕` — Режим «Не беспокоить» (DND — подавление проактивных реплик);
     - `📌` — Переключатель `Always-on-Top` / `Click-through` (с гарантированным выходом из click-through через хоткей/трей/кнопку);
     - `⚙️` — Развернуть в режим Студии.

2. **Режим 2: «Студия / Единый центр настроек» (`Studio Drawer Mode`)**
   - По клику на `⚙️` окно плавно расширяется (`360px → 1060px`), проявляется боковая панель `div.side` и рельса навигации `nav.rail`.
   - **Никакой перезагрузки WebGL:** 3D-сцена остаётся в том же canvas слева.
   - **Все настройки фреймворка в одном месте:** `config_hub.py` объединяет настройки `JAWL` (`settings.yaml`, `interfaces.yaml`, `SOUL.md`), `Companion` и `VoiceMem` в человекочитаемые категории по органам чувств (Личность и Задачи, Голос и Дуплекс, Зрение и Системный звук, Облик и Физика, Безопасность HostOS 0–3). Оригинальный веб-UI JAWL пользователю открывать больше не нужно.

3. **Единое ядро для OBS (`?mode=obs` на порту `8766`)**
   - Вместо устаревшего `avatar-scene.js` презентационный контур использует то же рендер-ядро `app-scene.js` в read-only режиме `?mode=obs` (прозрачный фон, скрыт HUD, нет управляющих токенов, один audio owner в основном клиенте).
   - Устаревший `frontend/index.html`, двухоконный `--legacy-shell` и `rust-client/` выводятся из активного контура после проверки паритета.

## 2. Эволюция VRM-модели и системы анимаций

В `desktop/app-scene.js`, `avatar-motion.js` и `avatar-physics.js` уже заложен сильный процедурный фундамент (дыхание, перенос веса, микро-жесты, `EMOTION_BODY` всплески, авто-выравнивание рук VRM 0.x/1.0 и кастомный spring-интегратор `FIXED_STEP = 1/60`). Следующие шаги гармонизации:

1. **Консолидация Pose Owner:**
   - Объединить разрозненные процедурные слои (`applyIdle` в `app-scene.js` и `avatar-motion.js`) в единый детерминированный контроллер позы с чистым графом состояний: `idle ↔ listening ↔ thinking/working ↔ speaking`.
2. **Визуально читаемое состояние `thinking / working`:**
   - Сейчас `thinking` мапится в `listening` (`mode === 'thinking' ? 'listening' : mode`). Для двухпоточного режима (когда JAWL в фоне пишет код, ищет в памяти или реверсит в Ghidra) нужна отдельная поза `working`: лёгкий наклон головы, взгляд в сторону экрана/рабочей области, периодическая задумчивая микро-анимация.
3. **Псевдо-виземная артикуляция губ (богатый Lip-Sync без тяжёлого фонематического движка):**
   - Заменить модуляцию одного блендшейпа `'aa'` от RMS громкости на многоканальную артикуляцию (`'aa'`, `'oh'`, `'ee'`, `'ih'`, `'ou'`), где огибающая громкости и частотный/шумовой паттерн речи плавно переключают гласные блендшейпы. Это уберёт эффект «хлопающей челюсти» на длинных русских фразах.

## 3. Многоуровневая агентная архитектура (Три скорости времени)

Чтобы компаньон был одновременно **живым собеседником (отклик < 1–2 с)**, **глубоким инженером (кодинг, моды, реверс в Ghidra/x64dbg)** и **напарником в играх (реакция 16–50 мс)**, один JAWL работает через три скоординированных временных контура без раздвоения личности:

```text
┌────────────────────────────────────────────────────────────────────────────┐
│ СЛОЙ 3: Глубокий Агентный Контур (JAWL Deep Task & Memory Lane)            │
│ Цикл: 3–60+ секунд (асинхронный фон)                                       │
│ • Полный ReAct, HostOS 0–3, терминал, написание модов, Ghidra / x64dbgMCP  │
│ • Долговременная память (SQL / Vector / Graph / Daily Journal)             │
│ • Не блокирует голосовой чат! Шлёт короткие прогресс-события в Слой 2.     │
└───────────────────▲────────────────────────────────────────┬───────────────┘
                    │ Поручения / Факты                      │ Чекпоинты («Нашла адрес в памяти...»)
┌───────────────────┴────────────────────────────────────────▼───────────────┐
│ СЛОЙ 2: Быстрый Разговорный и Эмоциональный Контур (Fast Duplex Lane)      │
│ Цикл: 0.5–1.5 секунды (микро-тики диалога)                                 │
│ • Живая беседа на лету, совместный просмотр фильмов/аниме, обсуждение      │
│ • Управление очерёдностью речи (backchannel, паузы, мгновенный barge-in)   │
│ • Выдача коротких голосовых реплик в OmniVoice и эмоций в VRM              │
└───────────────────▲────────────────────────────────────────┬───────────────┘
                    │ События игры / Сенсорные вектора       │ Тактические намерения («прикрой», «исследуй»)
┌───────────────────┴────────────────────────────────────────▼───────────────┐
│ СЛОЙ 1: Моторно-Тактический и Рефлекторный Слой (Game & Reflex Layer)      │
│ Цикл: 15–100 миллисекунд (10–60 Гц)                                        │
│ • Латентные сенсорные рефлексы (EmbeddingGemma 2) → мгновенная мимика VRM  │
│ • Игровой контроллер (мод-мост BepInEx/UE4SS/Lua/Memory/Input)             │
│ • Навигация, бой, следование за игроком в реальном времени без лага LLM    │
└────────────────────────────────────────────────────────────────────────────┘
```

### Связка «Писать моды + Играть вместе»
Поскольку Слой 3 (`JAWL` + `G:\RE`) умеет реверсить игры и писать код, компаньон может **сам создавать себе игровой мост (Game Bridge)**:
- Слой 3 анализирует игру или пишет лёгкий мод/плагин, открывающий локальный сокет телеметрии и команд;
- Слой 1 держит 30–60 Гц управление персонажем внутри игры;
- Слой 2 шутит, предупреждает об опасности голосом и принимает твои голосовые просьбы (*«Прикрой меня, я хилюсь!»*), переводя их в тактические состояния Слоя 1.

## 4. Full-Duplex Голос: `DuplexCascade` + `OmniVoice` + быстрый ASR

Классический полудуплексный каскад с VAD (`Ждём 1 сек тишины → Batch ASR → Полный ответ LLM → TTS`) заменяется на архитектуру **VAD-Free Micro-Turn Cascade** по принципу [DuplexCascade (arXiv:2603.09180)](https://arxiv.org/abs/2603.09180):

1. **Отказ от жёсткого VAD в пользу микро-тиков (`overlap_window ≈ 0.5–0.6 с`):**
   - Аудиопоток не ждёт долгой тишины. Каждые 500–600 мс инкрементальный прирост слов (или `<|no voice|>`) вместе с акустическим контекстом подаётся в быстрый контур.
2. **Семантическое управление очерёдностью речи через 6 спецтокенов:**
   - `<|user is talking|>` — пользователь продолжает фразу, компаньон молчит и слушает;
   - `<|user is thinking|>` — пользователь сделал паузу/хезитацию в середине незаконченной грамматической конструкции; компаньон **не перебивает** и ждёт;
   - `<|assistant_backchannel|>` — пользователь рассказывает длинную историю или смотрит сцену; компаньон коротко вставляет живое подтверждение (*«Угу», «Да ладно?», смешок*), не забирая ход;
   - `<|user finish talking|>` — смысловой конец реплики распознан мгновенно (без секундной задержки VAD), тут же стартует генерация ответа;
   - `<|user interruption|>` — пользователь заговорил поверх компаньона; мгновенный сброс очереди синтеза и воспроизведения (`OmniVoice reset`).
3. **Потоковый синтез `OmniVoice` (микро-чанки):**
   - Текст из микро-ходов сразу уходит короткими фразами в `OmniVoice` (с сохранением клонированного тембра и эмоциональной окраски), обеспечивая задержку до первого звука на уровне сотен миллисекунд.

## 5. Нестандартное использование `EmbeddingGemma 2` (Мультимодальная Сенсорная Кора)

По принципу [eg2.haku.sh](https://eg2.haku.sh/) мультимодальная модель **EmbeddingGemma 2** (где `Audio + Image + Video + Text` находятся в едином латентном пространстве) используется не просто как архивный текстовый эмбеддер для БД, а как **высокочастотная сенсорная кора (System 1)** на 10–20 Гц, снимающая 90% нагрузки с тяжёлой VLM и обогащающая ASR:

1. **Zero-Decoder Visual Probe (Мгновенное зрение вместо постоянных вызовов VLM):**
   - Предвычисленная в RAM матрица векторов тысяч русских/английских концептов (типы окон, состояния игр, эмоции персонажей аниме/фильмов, UI-события).
   - Кадр экрана проходит через лёгкий vision-энкодер за ~15–20 мс и умножается на матрицу концептов (`matmul`) **без авторегрессионной генерации токенов**.
   - Тяжёлая VLM (`Bonsai 8986`) вызывается только тогда, когда нужен детальный OCR мелкого текста/кода по явному запросу.
2. **Сверхбыстрый потоковый ASR + Чтение интонации по методу `eg2`:**
   - Линейный проектор (`reader`) поверх аудио-энкодера EmbeddingGemma 2 переводит короткие аудио-слайсы напрямую в словарный банк для микро-ходов `DuplexCascade`.
   - Одновременно тот же аудио-вектор даёт **аффект и интонацию голоса владельца** (смех, усталость, сарказм, тревога, шёпот), которых нет в голом текстовом транскрипте.
3. **Одновременное восприятие Фильмов, Аниме и Музыки (Audio-Visual Vibe Fusion):**
   - Системный звук больше не слеп к инструментальной музыке и саундтрекам: аудио-вектор классифицирует жанр, темп, настроение музыки и звуковые эффекты (взрывы, дождь, бой).
   - Поскольку вектор кадра экрана и вектор музыки лежат в одном пространстве, `perception_fusion.py` вычисляет их согласованность и передаёт в JAWL единый слепок: *что происходит на экране + что говорят персонажи фильма + какая играет музыка*.
   - **Co-watching etiquette:** во время плотных диалогов в фильме/аниме компаньон отыгрывает реакцию лицом/телом VRM, а голосовые реплики выдаёт только в смысловые паузы между диалогами.
4. **Латентные рефлексы VRM-аватара (задержка ~20 мс в обход LLM):**
   - Резкое изменение вектора экрана/звука (скример, взрыв в игре, внезапный поворот сцены) напрямую триггерит эмоциональный импульс (`EMOTION_BODY`) и взгляд (`lookTarget`) VRM-модели за 20 миллисекунд — тело реагирует мгновенно, а голосовой комментарий от LLM догоняет через секунду, как у живого человека.
5. **Семантический детектор смены сцены (Attention Trigger):**
   - Вместо шумного попиксельного diff вычисляется косинусная близость соседних кадров `cos_sim(E(frame_t), E(frame_{t-1}))`. Резкое падение близости означает настоящую смену контекста (новое окно, новая сцена в аниме) и пробуждает `Attention` / `Heartbeat`.
6. **Непрерывная векторная память дня (`Episodic Timeline` без raw-видео архива):**
   - Секундные мультимодальные слепки (экран + звук + речь) хранятся как компактные вектора (~10 МБ/час), позволяя находить любой момент дня по кросс-модальному запросу (*«вспомни сцену днём, где играло грустное пианино и был тёмный лес»*) без нарушения запрета на хранение сырого видео.

## 6. Три паттерна ускорения JSON-цикла JAWL (Устранение 4–6 с лага без потери ReAct)

Главная причина высокой задержки (4–8 с, а при повторных шагах до 27 с) в штатном цикле JAWL — не стоимость `json.loads()`, а структура генерации и многошаговый `ReactLoop`:
1. Модель сначала генерирует 50–150 токенов поля `thoughts` и синтаксис `tool_calls` перед тем, как дойти до текста ответа в `terminal_send_message`;
2. `ReactLoop` ждёт закрытия всего JSON перед отправкой текста в TTS;
3. После выполнения `terminal_send_message` цикл делает **второй запрос в LLM** для формального закрытия такта.

Чтобы снизить задержку до **0.9–1.5 с** уже на текущем JSON-протоколе (этапы `D2-01` / `D2-02`) и до **0.3–0.7 с** в целевом дуплексе (`H2`/`H3`), фиксируются три правила:

1. **Инверсия порядка полей / Speech-First Prefix (Сначала речь — потом мысли и инструменты):**
   - Для интерактивного хода компаньона (`_companion_turn_id`) голосовая реплика (`speak` / короткий ответ) выносится **первым полем** (либо перед блоком инструментов), а `thoughts` ограничиваются кратким планом только при вызове реальных системных инструментов.
   - Видеокарта выдаёт первые слова ответа на 5–10-м токене генерации (через 200–300 мс), а не после 120 токенов скрытых рассуждений.
2. **Потоковое извлечение речи до закрытия JSON (`Stream-Before-Close` в `native_jawl_delivery`):**
   - Не ждать финальной закрывающей скобки `}` всего JSON-ответа LLM. Инкрементальный парсер вычленяет первую законченную синтагму/предложение из потока токенов речевого поля и немедленно отправляет её в `OmniVoice`, пока модель дописывает хвост JSON и аргументы фоновых тул-коллов.
3. **Одношаговый быстрый выход (`Single-Step Fast-Exit` для разговорных реплик):**
   - Если на первом шаге `ReactLoop` модель вызвала только речевой ответ (`terminal_send_message`) и не вызывала инструментов чтения/изменения среды (`memory.*`, `hostos.*`, `terminal.exec`, `mcp.*`), цикл завершается **за 1 шаг LLM** без повторного вызова модели «подтверди завершение». Это вдвое сокращает расход токенов и полностью убирает холостой второй раунд.

## 8. Зрение как орган управления ПК (Grounding & Affordance Lane)

Тот же сенсорный проход EmbeddingGemma 2, который описывает кадр, обязан выдавать
пригодные для действия цели. Это не вторая VLM и не второй тяжёлый проход:
UIA-дерево, OCR-боксы и 29 пространственных токенов `last_hidden_state`
переиспользуются совместно с описанием.

**Поток одного кадра:**

1. **Захват:** кадр дисплея + UIA-дерево активного окна + OCR-боксы + 29 патч-токенов EG2.
2. **Grounding (кандидаты действия):** список
   `{role, label, bbox, center, confidence, source, element_ref, element_sha256}`:
   - **UIA** — авторитетный источник для доступных контролов (кнопки, поля, вкладки,
     пункты меню); даёт `element_ref` + `element_sha256` для policy-safe действия;
   - **OCR** — bbox текста для canvas/видео/игр, где UIA-дерева нет;
   - **EG2** — роль аффорданса (`button`, `input`, `tab`, `menu`, `icon`, `slider`,
     `checkbox`) и 5-зонная карта кадра; пиксельные границы уточняют bbox;
   - **confidence-гейт:** действие разрешено только при достаточной уверенности и
     свежем `observation_token`/`observation_digest`.
3. **Планирование:** существующий `VisionActionPlan` (1–8 действий, strict schema,
   postcondition). При наличии UIA запрещены слепые клики по координатам.
4. **Исполнение:** `VisionPlanExecutor` → HostOS policy → native JAWL skills
   (`HostOSDesktop.*`); каждое действие обязано иметь проверенный postcondition.
5. **Реальное время:** UIA+OCR ≈ 5–30 мс, EG2 ≈ 70–130 мс; кэш по digest,
   без записи сырых кадров. Управление и описание используют один embedding-проход.
6. **Безопасность:** sensitive-window block, redaction, policy level, dry-run,
   подтверждение для необратимых действий; один audio/action owner, идемпотентные
   ключи, отмена по Stop.

**Инвариант:** зрение для управления не имеет права работать по «сырым» координатам
без confidence-гейта, свежего observation token и проверяемого postcondition.

**Текущая реализация (20 Oct):** `DetailedSensoryDescriber` + `Eg2VisionDescriber`
на CPU (0 МБ VRAM); сценарные/персональные/сюжетные/мемные банки расширены до ~158
концептов и кэшируются в `.npz` (тёплый старт 2 мс). Лаунчер поддерживает
`-EnableScreenWatch -Eg2Vision` без внешнего VLM; `PerceptionFusion` подмешивает
свежий фон восприятия в каждый контекстный ход, а `AmbientAudioASRBridge` получает
жанр/BPM/тональность/настроение через `Eg2AudioDescriptionProvider`.
