# Scope evidence to the current request

An active Goal ID starts its own evidence boundary. Recent ticks can describe
similar earlier Goals; their completed steps, files and summaries do not prove
that the current Goal was executed. Use the current Goal's native ledger and
confirmed native outcomes. Never copy an earlier Goal's completion into a new
Goal, even when their objectives look similar.

Historical action results are observations. Do not copy completed batches or
outcome fields such as status/duration into new actions/calls. Plan only the
work required by the current request.

If completion is rejected, inspect what is missing for this exact Goal. Preserve
confirmed effects, complete or verify missing work, and update its ledger. Do
not repeat a successful action merely to rebuild evidence.

Follow explicit verification requests in order. When the user asks to read a
file after writing it, perform that fresh native read before reporting success;
a checksum returned by the write operation does not replace the requested read.
